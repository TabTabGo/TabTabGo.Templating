# Changelog

All notable changes per release line. The line is the major version: 8 = .NET 8, 10 = .NET 10, 11 = .NET 11. Spec and decisions:
`tabtabgo/docs/templating-modernization/` in the ttg-workspace (row ids such as S-3 or X-2 refer to its section 6).

## 11.0.0

Target: net11.0 on SDK 11.0.100 (GA); Microsoft.Extensions 11.0.0 (GA). No API change compared with 10.0.0: ApiCompat in assembly mode (`.github/scripts/apicompat.py`) compares
the packed assemblies with the published 10.0.0 ones; package validation has no baseline (it cannot compare net10.0 with net11.0). `Microsoft.Extensions.Options`,
`DependencyInjection.Abstractions` and `Configuration.Abstractions` are no longer package references: they ship in the net11.0 shared framework (NU1510).
Lock files are committed and restore is always `--locked-mode`.
Verified by running it: the packed packages were referenced from a plain `net11.0` console app (`Microsoft.NETCore.App` only, plus the consumer's own `Microsoft.Extensions.DependencyInjection`), which registered the options through `AddTabTabGoTemplating`, rendered a Liquid template and wrote a workbook; `Microsoft.Extensions.Options`, `DependencyInjection.Abstractions` and `Configuration.Abstractions` were resolved from the shared framework (they are not copied to the output), while `Configuration`, `.Binder` and `.Json` come with the package.
ApiCompat script fixes: the reference set is the declared dependencies from the lock files (no stale packages from the shared cache, no `TabTabGo.*`), versions are compared as versions (10.0.10 above 10.0.9, a release above its preview), `--allow-missing-baseline` skips only the packages whose baseline is missing, and a transient nuget.org error is retried three times. The release order (v10.0.0 published before a v11 tag) is documented in the README.

## 10.0.0

Target: net10.0. Includes every 8.0.4 fix unchanged (fresh context per render, regex time-outs that propagate, include confinement, `AppSetting` opt-in, safe XML, JSON workbook
mode, no temp files). No public API of 8.0.4 was removed or changed.

### Added
- `TemplatingOptions`: `MaxIterations`, `RenderTimeout`, `MaxOutputCharacters`, `MaxDepth`, `AllowAbsolutePaths`; every numeric option is validated by the engine constructors.
- `RenderLimitExceededException`, and internal guards (bounded `capture`, `Append`, `Prepend`, `Join`, `Replace`, `ReplaceFirst`, `RemoveFirst`, `Plus`, `Times`, `Concat`) that return what the stock DotLiquid 2.3.260 filters return within the limit.
- `CountryName(code, culture)`, exact `decimal` overloads of `FormatNumber`.
- OpenXml: valid default stylesheet, one worksheet part per JSON-workbook sheet, per-render `RenderSession`.
- Test kit (`TabTabGo.Templating.TestKit`): golden helpers for text and workbooks, workbook builder; 31 Liquid and 6 workbook goldens; coverage gate in CI.

### Changed (behaviour; see the release notes in the README)
- Output, capture blocks and growing filters are capped at `MaxOutputCharacters` and throw instead of truncating; `FullPath` is relative; filters format with the render culture and parse
  invariantly; dates default to UTC; OpenXml cells are typed by JSON token, dates are serials, leading zeros stay text, tables keep row gaps and shift merged cells, filters and other tables.
- `RenderString` refuses templates longer than `MaxTemplateCharacters`, default 262 144 (V10-17; parse cost at 1 000 000 characters is 4-11 s of CPU against 0.5-1.4 s at 262 144; raise it explicitly for larger templates).
- `Configuration.GetTemplatingConfiguration()` and `TemplatingConfigurationSection.SectionName` are obsolete; the method reads an optional `appsettings.json`.
- Humanizer 3 (`Humanizer.Core`, `.ar`), Microsoft.Extensions 10.0.14, Newtonsoft.Json 13.0.4, DotLiquid 2.3.260, Open XML SDK 3.5.1, System.Linq.Dynamic.Core 1.7.4.

### Fixed
- B-3..B-6, B-9 (engine state, null/list data, culture, object-typed members); S-6, S-10..S-12 (paths, limits, links); F-1..F-15 (filters); F-16, F-17 (configuration);
  X-4..X-21 (workbooks), B-7 (parallel workbooks); P-7 (nullability, `-warnaserror` clean).

### Fixed (fix round after the diff and security review)
- OpenXml JSON workbook: a missing `$.StyleMap` no longer writes every row empty; `InlineString` writes its `<is>` element, `SharedString` is written inline, `Error` cells accept only Excel error literals; invalid XML characters are removed from cell text;
  an empty `Workbook.Sheets`, an invalid sheet name and a duplicate or colliding sheet id throw `ArgumentException`; the date default style 5 applies only to the generated stylesheet (or a loaded one with more than five formats); the style lookup compares keys directly
  (no JSONPath filter built from data); a stylesheet reached through a symbolic link outside `StylesheetRoot` is refused.
- `Filter` (dynamic LINQ) checks the parsed expression tree against an allow-list (no `PadLeft`, `PadRight`, `Replace`, `Insert`, `Concat`, `Join`, `Format`, string `+`; constant numbers up to 10 000 for string methods); these allocated outside `MaxOutputCharacters`.
- The parse thread reserves 512 KB plus 8 KB per allowed nesting level (1 312 KB by default) instead of 256 MB; a DotLiquid without the internal tokenizer falls back to the stock parse instead of `TypeInitializationException`.
- Round 2: `Filter` expressions are limited to 1 000 characters, 64 nesting levels and 32 calls, parse on a 16 MB-stack thread, compare ordinally and check the render time-out per row; a stack overflow in the guard's walk is a catchable exception; a symbolic-link chain that leaves `StylesheetRoot` or the include root through another link is refused (links are now resolved the way the OS does); the fallback scan counts `{%-` tags and reserves the 256 MB parse stack; empty number/boolean/date cells are empty cells; sheet names are unique ignoring case and may not be `History` or start/end with an apostrophe; an out-of-range `StyleIndex` is refused; `CreateExcelDoc(fileName, ...)` leaves no file on failure.
- Round 3: a dangling or unreadable include file throws "Template not found" without a server path; the nesting scan counts the built-in block tags by name (not through DotLiquid's registry) and the fallback scan counts `{# #}`; `Filter` caches compiled predicates by criteria text (256 entries, only guard-approved ones, never refusals), parses short plain criteria on the caller's thread only when they are at most 64 characters and 8 levels deep, contain no `[`, `{`, `new` or `=>`, and at least 256 KB of stack verifiably remain (everything else, such as criteria with `it["k"]`, uses the 16 MB thread on a cache miss; the cache covers repeats), and counts each call once toward the 32-call limit.
- Round 3, JSON workbook (behaviour changes): a Number cell must hold a finite number (written in the canonical invariant form) and a Boolean cell true/false/1/0, otherwise `ArgumentException`; whitespace-only text is an empty cell; a numeric Date value (or numeric text) from 1 to 2 958 465 is an Excel serial and is written as the date serial, while an unparseable date throws instead of being dropped silently; sheet names may not contain control characters or lone surrogates; `SheetId` must be a whole number from 1 to 65534 (the schema's maximum); at most 255 sheets (the writer's hard ceiling), with linear id and name generation.
- Round 5: a criteria the caller's thread cannot finish for lack of stack is retried on the 16 MB thread, not refused; `[` and `]` count as nesting like parentheses; an unclosed `{#` no longer stops the fallback nesting scan (the 256 MB parse stack given to the fallback path covers any remaining undercount); every numeric conversion of a JSON-supplied value (`SheetId`, `StyleIndex`, `SIndex`, column `Min`/`Max`/`Width`, `Collapsed`, Number, Boolean and Date cells), including values beyond any numeric type, is an `ArgumentException` and never an `InvalidCastException`, `FormatException` or `OverflowException`; the fallback-scan differential test no longer asserts a gap bound.
- Round 7, notes: syntax errors from `Filter` (Dynamic LINQ `ParseException`) are now `ArgumentException` as well; `OutOfMemoryException` is not wrapped and propagates; a Date cell in the years 1 to 99 is an `ArgumentException` (the range is checked before `ToOADate`).
- Fix round after the code and security review: the link resolution of the include loader and the stylesheet loader is one shared source (`RealPath`, in the base package) and runs inside the guarded read, so an unreadable directory, a link loop or a chain over 32 links is "template not found" / "stylesheet not found" without any path; the compiled-`Filter` cache evicts only its least recently used entry (it used to be cleared whole when full, so one template generating distinct criteria wiped every other template's entries). Criteria with `[` (every `it["k"]`) still parse on the large-stack thread on each cache MISS, because indexer shapes needed up to 337 KB in measurements, more than the margin probe guarantees; the cache covers repeats, and the LRU keeps hot entries alive while a flood of distinct criteria pushes out only its own (1,000 distinct `it["k"]` criteria: about 3,450 calls/s before the LRU change and about 3,500 after on the development laptop: the throughput is the thread start per miss, which this change does not remove, and what the LRU changes is that hot entries survive the flood).
- Internals that the base package shares with the Dotliquid and OpenXml packages (`RealPath`, `TemplatingOptionsValidator`) are frozen within a major version: the three packages are released together, and an internal contract between them changes only with a new major.
- Documented, not changed: `include`/`extends` partials are trusted input and not depth-scanned, and the `.xlsx` template file is read without a size cap (README notes).
- Exception messages of the JSON workbook validators never contain a JSON value (no cell text, number, sheet name or style key; the field is named, and no inner exception is attached because its message quotes the value): a workbook comes from data and may hold personal data. One test feeds a sentinel through every validator path.
- CI scripts: the vulnerability gate finds the report by trying each `{` (a warning line before it containing a brace no longer fails a clean audit), treats a non-object advisory entry as a finding and still fails closed when no report parses; the `-local` pin guard looks only at the version attributes and elements, not at descriptions or comments.
- Round 10: column `Min` and `Max` are capped at 16384 (Excel's last column; a larger range is schema-invalid): the rule is now "required whole numbers from 1 to 16384, `Min` <= `Max`", otherwise `ArgumentException` and no file is written.
- Round 9: a JSON `null` is "not given" for the optional column and row members (`Width`, `BestFit`, `Collapsed`): it means the default instead of throwing (`"Width": null` used to throw); the text `"true"`/`"false"`/`"1"`/`"0"` is accepted for `BestFit` and `Collapsed` (any case), any other text is refused.
- Round 8: column `BestFit` values other than true/false/1/0 (a number such as 2, -1, 0.5 or 1e400, text, empty text) are refused instead of being cast (`2` used to be written as true, `"1"` and `"abc"` threw `FormatException`); a missing `BestFit` is still false; column `Min` and `Max` are required, whole numbers from 1 (Excel columns start at 1; 0 is refused, and a missing one is no longer defaulted to 1) and `Min` may not exceed `Max`, otherwise `ArgumentException` and no file is written.
- Round 7: column `Width` must be a finite number from 0 to 255 (the schema range; fractions are fine), otherwise `ArgumentException`; the margin-probe tests no longer assume how much stack a helper frame consumes (they measure it on the thread, and the helper frames are real, un-inlined and touched), which made one of them fail on Linux x64.
- Round 6, notes: fractional indices (`StyleIndex`, `SIndex`, `SAlternativeIndex`, column `Min`/`Max`) are no longer rounded but refused, and `Collapsed` values other than true/false/1/0 are refused; column `BestFit` still uses Newtonsoft's cast and `Width` still accepts negatives and "NaN" (left for the row and cell limits work); the fallback `{#` scan is linear.
- Round 6: a stylesheet that cannot be read (no permission, a directory, a pipe) fails as "stylesheet not found", and malformed XML or a DTD as a generic `ArgumentException`, neither carrying a path, inner exception or `SourceUri`; include and stylesheet files are opened once on their resolved real path (a symbolic link must resolve inside the folder), verified on that same handle (seekable, at most 16 MB) and read through a byte-counting cap, so a file that grows while it is read is refused at 16 MB, and a directory or a link out of the folder is refused like a missing file. **Known limitation:** .NET cannot tell a named pipe, socket or device from an empty regular file before opening (measured: all report `FileAttributes.Normal`, length 0 and the same permission bits), and a plain open of a named pipe blocks, so the template and stylesheet folders must not be writable by untrusted parties (someone who can create a pipe there can already replace the templates); no native call is made because none is portable to musl, macOS and Windows alike; a `Filter` expression that parses but does not compile (`renew == 1`, some `??` shapes) is a short `ArgumentException`; JSON workbook: dates before 1900-03-01 (Excel's fake 29 February 1900 makes the OLE serial one off before it) and after 9999-12-31 are refused, a number from 1 to 60 is still accepted as an explicit serial, and StyleMap `SIndex`/`SAlternativeIndex` must be inside the stylesheet's cell formats like an explicit `StyleIndex`; the sheet count is checked before the list is copied. A date cell in a loaded stylesheet with five cell formats or fewer gets style 0 (a plain number): use a stylesheet with at least six cell formats or the generated one.
- `FormatDate "Now"` renders the UTC date (decision F-10); the `LocalizedDateFormatFilterTest` expectation was a test bug and now pins the clock.
- Filter narrowings that remain (breaking for templates that used them on 8.0.x): `ToString` with any argument (e.g. `ToString("N2")`); `int`/`decimal`/`DateTime` `Parse`; `Convert.ToDateTime` and `Convert.ToString`; `DateTime` methods such as `AddDays`; a computed number, or one above 10 000, passed to a string method (e.g. `Substring(Length - 2)`); `Hash.Count` and array `Length`; `Split`, string `+`, and the methods that grow a string (`PadLeft`, `PadRight`, `Replace`, `Insert`, `Concat`, `Join`, `Format`, `Remove`, `Normalize`). Every string-taking overload of `IndexOf` (with a start index or count), `StartsWith`, `EndsWith`, `Compare` (including `Compare(a, i, b, j, n)`), `CompareTo` and string `<` `>` is now ordinal instead of culture-sensitive; `LastIndexOf`, `Compare`/`StartsWith`/`EndsWith` with a `CultureInfo` or `bool ignoreCase` argument, `CompareTo` with a non-string argument, a `StringComparison` given as a number (a cast `int`), and an explicit `StringComparison` other than `Ordinal`/`OrdinalIgnoreCase` are refused.
- The template cache is keyed by `MaxNestingDepth` as well and sweeps stale entries only when a new entry is added; partial names no longer accept a trailing newline.
- CI: the vulnerability gate fails closed (any `problems`, no projects, no sources, an empty `frameworks`); `NU1900` is an error; release tags accept ASCII digits without leading zeros only; `Version` and `TargetFramework` are read as XML.

### Fixed (fix round 4)
- JSON workbook (`JsonSpreedSheet`): a missing or non-array `$.Workbook.Worksheet.SheetData.Rows`, or a missing `SheetData`, is an `ArgumentException` (it silently produced an empty workbook, as v8 already refused it). A workbook of the wrong JSON shape (`Workbook.Sheets`, `Columns`, `Rows` or `Cells` not an array, an entry that is not an object, a non-text sheet `Name`) is an `ArgumentException` instead of Json.NET's `InvalidOperationException`/`InvalidCastException`; messages name the path, never a value; nothing is written. A JSON `null` `Columns` or `Cells` is "not given".
- Partials read by `include`/`extends` through the render's file system are scanned against `MaxNestingDepth` before DotLiquid parses them (a deeply nested partial bypassed the S-13 guard).
- Tests that returned silently as root or on Windows now skip visibly (`Assert.Skip`).
- Release guard: the stable-tag pin check reads single-quoted attributes and the `<Version>` element form, ignores comments, and resolves `$(Property)` references before looking for pre-release and `-local` versions.

### Removed
- Dependencies on `TabTabGo.IO.Utilities` and `Common.Logging.Core`; `Newtonsoft.Json` from the base package.

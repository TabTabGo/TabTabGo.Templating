# Changelog

Release line 8 (.NET 8). Spec and decisions: `tabtabgo/docs/templating-modernization/` in the ttg-workspace.

## 8.0.5

Backport of the S-13 parse guard from v10/v11 (additive).

### Added
- `TemplatingOptions.MaxNestingDepth` (default 100, validated: at least 1). `RenderString` and template files count block nesting over DotLiquid's own tokens before `Template.Parse`; a deeper template throws `DotLiquid.Exceptions.SyntaxException` naming `MaxNestingDepth` instead of overflowing the stack (an uncatchable process crash below 60 KB of template text). The parse runs on a thread whose stack is sized from the limit. The template-file cache key includes the limit.
- Partials read by `include`/`extends` through the render's file system (`TemplatesPath`, or the directory of the rendered file) are scanned against `MaxNestingDepth` before DotLiquid parses them; a deeper partial fails the include with a `SyntaxException` naming the option (DotLiquid may render it inline as its error text). A file system the host assigns to `Template.FileSystem` is not wrapped.
- OpenXml JSON workbook: a workbook of the wrong JSON shape (`Workbook.Sheets`, `Columns`, `Rows` or `Cells` not an array, an entry that is not an object, a non-text sheet `Name`) is an `ArgumentException` instead of Json.NET's `InvalidOperationException`/`InvalidCastException`; messages name the path, never a value; nothing is written. A JSON `null` `Cells` is "not given".
- CI scripts: `vuln_gate.py` reads the report past a warning line that contains `{` and exits 2 when no report is readable (same as v10/v11).
- The rest of the v8 limits statement is unchanged: no iteration cap, render time-out, output cap or template size cap on this line (use v10 or v11).

## 8.0.4

Security backport for the .NET 8 line: `AppSetting` opt-in, confined includes, dynamic-LINQ restrictions (`FilterBy`/`FilterByPrefix`), regex and XML bounds, per-render file system and context, safe template cache, OpenXml
JSON-workbook mode and booleans, no temp files.

**The v8 line has no render limits.** No iteration cap, no render time-out, no output cap, no nesting cap and no template size cap exist on v8 (they exist on v10 and v11 and are not backported). Do not render untrusted templates with v8.

### Fixed (fix round)
- OpenXml JSON workbook: missing `$.StyleMap`, `InlineString`/`SharedString`/`Error` cells, invalid XML characters, sheet list and sheet name validation, duplicate sheet ids, default date style, style lookup by direct key comparison, stylesheet links outside `StylesheetRoot`.
- Round 2: empty number/boolean/date cells are empty cells; sheet names are unique ignoring case and may not be `History` or start/end with an apostrophe; an out-of-range `StyleIndex` is refused; `CreateExcelDoc(fileName, ...)` leaves no file on failure; a stylesheet symbolic-link chain that leaves `StylesheetRoot` through another link is refused (links are resolved the way the OS does). v8's `EnhancedLocalFileSystem` does no link resolution at all: a symbolic link inside the include folder is followed wherever it points, so **v8 must not be used with a template directory that untrusted parties can write to** (not changed).
- Fix round after the code and security review: a JSON `null` `StyleIndex` or `SAlternativeIndex` is "not given" (the `Format`/StyleMap lookup stays active; it used to force style 0); a missing or non-array `$.Workbook.Worksheet.SheetData.Rows` is an `ArgumentException` (it was a NullReferenceException); unparseable Date text is an `ArgumentException` like a bad Number or Boolean (it was written as an empty cell). The warning above still stands: Date cells that do parse are still written as culture text on this line.
- Exception messages of the JSON workbook validators never contain a JSON value (no cell text, number, sheet name or style key; the field is named, and no inner exception is attached because its message quotes the value): a workbook comes from data and may hold personal data. One test feeds a sentinel through every validator path.
- Round 10: column `Min` and `Max` are capped at 16384 (Excel's last column; a larger range is schema-invalid): the rule is "required whole numbers from 1 to 16384, `Min` <= `Max`"; an empty `Columns` array no longer writes an empty `<cols/>` element (schema-invalid).
- Round 9: a JSON `null` is "not given" for `Width`, `BestFit`, `Collapsed`; a missing `Columns` array is an `ArgumentException` ("Columns is required"; it was a NullReferenceException); the text `"true"`/`"false"`/`"1"`/`"0"` is accepted for `BestFit` and `Collapsed` (any case). v8 requires a `SheetId` on every sheet, while v10 and v11 generate a missing one.
- Round 7: column `Min`/`Max` must be whole numbers from 1 (Excel columns start at 1; 0 is refused) (and `Min` may not exceed `Max`, and both are required), `Width` a finite number from 0 to 255, `BestFit` and row `Collapsed` true/false/1/0; anything else (BigInteger, negative, NaN, infinity, 4294967296, fractional indexes, non-numeric or empty text) is an `ArgumentException`, and the file overload writes nothing. Fractional `Min`/`Max` are refused instead of rounded.
- Round 6: a stylesheet that cannot be read (no permission, a directory, a pipe) fails as "stylesheet not found", and malformed XML or a DTD as a generic `ArgumentException`, neither carrying a path, inner exception or `SourceUri`; include and stylesheet files are opened once and verified on that same handle (seekable, at most 16 MB), read through a byte-counting cap, and the stylesheet loader opens the resolved real path (a link out of the folder is refused). **Known limitation:** .NET cannot tell a named pipe or a device file from an empty regular file before opening (all report `FileAttributes.Normal` and length 0), and a plain open of a named pipe blocks, so the template and stylesheet folders must not be writable by untrusted parties; no native call is made because none is portable to musl, macOS and Windows alike; the "Illegal template path" error names the requested name, not the absolute path; StyleMap `SIndex`/`SAlternativeIndex` must be inside the stylesheet's cell formats (the generated stylesheet of this line has none, so a StyleMap index above 0 needs a loaded stylesheet); the sheet count is checked before the list is copied. Fractional `StyleIndex`, `SIndex` and `SAlternativeIndex` are no longer rounded but refused.
- Round 5: `SheetId` is capped at 65534 (the schema maximum, uint.MaxValue before); every numeric conversion of `SheetId`, `StyleIndex`, `SIndex` and `SAlternativeIndex`, including values beyond any numeric type, is an `ArgumentException`; Number cells are formatted and parsed invariantly under any thread culture.
- Round 3: a dangling or unreadable include file throws "Template not found" without a server path; a Number cell must hold a finite number (canonical invariant form) and a Boolean cell true/false/1/0, otherwise `ArgumentException`, and whitespace-only text is an empty cell; sheet names may not contain control characters or lone surrogates; `SheetId` must be a whole number from 1 to 65534; at most 255 sheets; the source builds with SDK 10 as well (explicit `Enumerable.Reverse`).
- **On v8, Date cells in JSON workbooks are written as culture-formatted text in a numeric cell, and the date value is LOST or WRONG when the workbook is opened in a spreadsheet (a tested example: LibreOffice reads 2024-05-06 as 5 and 2000-01-02 as 1). Do not use Date cells in JSON workbooks on v8; use v10 or v11.**
- Known limitation, not fixed on v8: the JSON workbook mode still has the legacy shape (the generated stylesheet is empty, so style indexes above 0 need a loaded stylesheet, and dates are written as culture text parsed with the thread culture; a missing `Columns` array is now an `ArgumentException`). Use v10 or v11 for a complete JSON workbook mode.
- Include names no longer accept a trailing newline.
- CI: the vulnerability gate fails closed; release tags accept ASCII digits without leading zeros only; `Version` and `TargetFramework` are read as XML.
